# Fase 12.1 — Crash al abrir vídeo (SIGSEGV)

## Problema

Al pulsar **OK** en el diálogo «Análisis del archivo multimedia», la aplicación
se cerraba de inmediato con **segmentation fault**. El análisis ffprobe y la
selección de pistas funcionaban correctamente; el fallo ocurría al cargar el
reproductor mpv embebido.

## Síntoma

En terminal:

```text
Non-C locale detected. This is not supported.
Call 'setlocale(LC_NUMERIC, "C");' in your code.
zsh: segmentation fault (core dumped)  python3 gui_app.py
```

Secuencia en la GUI:

1. `Archivo → Abrir vídeo…` — OK
2. Diálogo de análisis — OK
3. Pulsar **OK** — la ventana desaparece y la app entera termina

## Causa

**Componente:** libmpv (cliente **python-mpv**), invocado desde
`_load_video_from_path()` en `gui_app.py`.

**Mecanismo:**

1. `gui_app.py` importa `mpv` al arrancar; python-mpv establece `LC_NUMERIC=C`.
2. `QApplication(sys.argv)` (Qt/PySide6) **sobrescribe** `LC_NUMERIC` con el
   locale del usuario (p. ej. `en_US.UTF-8`).
3. Al crear `mpv.MPV(...)`, libmpv comprueba el locale en `mpv_create()`.
4. Si no es `C` o `C.UTF-8`, libmpv imprime el aviso y **devuelve un handle
   nulo** (`NULL`).
5. python-mpv no comprueba el handle nulo y llama a `_mpv_set_option_string`
   sobre `NULL` → **SIGSEGV** (línea ~875 de `mpv.py`).

El mensaje de locale **no es solo una advertencia**: en libmpv 0.35.x es la
condición que impide crear el contexto y provoca el crash en el binding.

FFmpeg/ffprobe no intervienen en el SIGSEGV (solo se usan antes, en el diálogo).

## Diagnóstico

1. **Trazado del flujo:** `open_video()` → `MediaInfoDialog.exec()` → OK →
   `_load_video_from_path()` → `mpv.MPV(wid=..., vo="gpu", ...)`.

2. **Reproducción controlada** (mismo orden de imports que `gui_app.py`):

   ```bash
   python3 -X faulthandler -c "
   import mpv
   from PySide6.QtWidgets import QApplication, QMainWindow, QFrame
   import sys, locale
   app = QApplication(sys.argv)
   print('LC_NUMERIC:', locale.setlocale(locale.LC_NUMERIC, None))
   # ... winId + mpv.MPV() → exit 139, faulthandler → mpv.py:875
   "
   ```

3. **Verificación del arreglo:** tras `locale.setlocale(LC_NUMERIC, 'C')`
   inmediatamente después de `QApplication`, `mpv.MPV()` se crea sin crash.

4. **Referencias:** documentación de [python-mpv](https://github.com/jaseg/python-mpv)
   (sección PyQT embedding); código fuente de mpv `player/main.c` (`check_locale`).

## Solución

Función `_ensure_mpv_numeric_locale()` en `gui_app.py`:

```python
def _ensure_mpv_numeric_locale():
    import locale
    locale.setlocale(locale.LC_NUMERIC, "C")
```

Llamadas:

| Ubicación | Motivo |
|-----------|--------|
| `main()` — justo después de `QApplication(sys.argv)` | Qt ya alteró el locale |
| `_load_video_from_path()` — antes de `mpv.MPV(...)` | Defensa ante cambios posteriores de Qt |

No se modifica la configuración de locale del sistema Debian.

## Compatibilidad

| Dependencia | Notas |
|-------------|-------|
| **Debian / locale usuario** | Fix solo dentro del proceso Python |
| **PySide6 / Qt** | Qt cambia `LC_NUMERIC`; patrón documentado por python-mpv |
| **libmpv 0.35.x** | Comportamiento verificado con `libmpv2` 0.35.1-4 |
| **python-mpv 1.0.8** | El binding no valida handle nulo tras `mpv_create()` |
| **FFmpeg** | Sin cambios |

Efecto lateral: `LC_NUMERIC=C` en el proceso puede cambiar el formateo decimal
de floats en logs o mensajes de esa sesión (impacto mínimo en esta app).
